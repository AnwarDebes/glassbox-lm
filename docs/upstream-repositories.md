# Upstream repositories

This page lists the repositories that the studies use or cite as code. The four under `AnwarDebes` (HGTM, Multi-HGTM, tm-llm-robustness-benchmark and Clause-Driven-LLM) are earlier repositories of the author of this one; the others are by other authors. One of them is vendored: a copy of `cair/GraphTsetlinMachine` is in the repository. Every other repository is referenced and not distributed. It is installed from its public address at a pinned commit, kept as a local reference clone, or kept as a local work copy. Commits, versions and licences are given as a file on disk records them; the entry reads "not recorded" where no file gives the value. Datasets are on the [data page](data.md) and papers in the [references](references.md).

Paths are cited from the repository root. In the table, `tm.lock`, `dl.lock`, `htm.lock`, `bootstrap.sh` and `htm_install.sh` stand for the files of these names in `studies/tm_language_model/env/`, and docs/02, docs/12 and docs/13 for the documents `02-verified-code-facts.md`, `12-design-changes.md` and `13-preregistration.md` in `studies/tm_language_model/docs/`. Experiment ids such as E6 and H3 are those of `studies/tm_language_model/docs/05-experiments.md`. The packages that the environments of tm_language_model take from the Python package index are pinned in the three lock files and are not listed here; decision_layer lists those of its environments in `studies/decision_layer/env_dl_freeze.txt` and `studies/decision_layer/env_htm_freeze.txt`, which are not lock files.

## Note 1: licences

The only licence that a file of the repository states for an upstream repository is the MIT licence of the vendored GraphTsetlinMachine. For the other `cair` repositories and for Tsetlin.jl the entry "MIT" is taken from the index of the reference clones (note 2), which names MIT for them and refers to the licence file of each clone. That index names no licence for the remaining repositories, so their entries read "not recorded". For Clause-Driven-LLM the licence is the one that the README of the clause_lm study reports.

## Note 2: reference clones

Twelve repositories were cloned on 2026-09-22 into `studies/tm_language_model/third_party/ref/`, a folder that git ignores and that is not distributed. The commit of a clone is its head on 2026-09-22, as an index kept with the clones records it. The index itself is not published, so this page is the published record; five of its commits are recorded in short form only. Two of the twelve clones are those of `cair/tmu` and of `cair/PyHierarchicalTsetlinMachineCUDA`; they share a table row with the pinned install of the same commit. The clones are read and cited, and no environment installs from them: `studies/tm_language_model/env/htm_install.sh` installs the hierarchical package from its public address at the pinned commit. Two code paths read the clone of the hierarchical package without importing it. The install script compares the hashes of the installed package files with those of the clone when the clone exists, and `studies/tm_language_model/experiments/ssl_r2_hao_diagnostics.py` parses the default settings of the package demos from the source in the clone.

The demo scripts `examples/MultiConceptDemo.py` and `examples/ANDOfXORsDemo.py` belong to `cair/PyHierarchicalTsetlinMachineCUDA`. Check 1a of the hierarchical_tm study runs the MultiConcept demo from a path given on the command line (`studies/hierarchical_tm/src/run_demo_seeded.py`), and no copy of the demo is distributed. The docstring of `studies/hierarchical_tm/src/text_driver.py` names a local copy with the suffix `79726a2`; what the suffix refers to is not recorded.

## The vendored package

`studies/tm_language_model/third_party/GraphTsetlinMachine/` holds the upstream files of the recorded commit without changes. Three upstream items are left out: `.devcontainer/`, `.gitignore` and `.gitattributes`. The package is the stock reference of the tm_language_model study and is not edited. The copy that the study may patch is `studies/tm_language_model/src/tmlm/kernels/graphtm_patched/kernels.py`; the README next to it records the SHA-256 of the stock kernel file.

## torchtsetlin

A copy of the package `torchtsetlin` (github.com/vlbthambawita/torchtsetlin, branch main, and the PyPI release 0.3.0) was kept as a reference for the clause_lm study. No source file of the five studies imports it. Its commit and its licence were not recorded, so it has no row in the table above.

## Clause-Driven-LLM

The clause_lm study used a copy of this repository that was downloaded on 2026-10-02 from the branch main as a source archive without version history, so the copy itself carries no commit id. The commit in the table was noted as the latest commit of the public repository on that day; its status is "recorded in project notes, not checked against upstream". The code of the study expects an unmodified reference copy at `references/code/Clause-Driven-LLM` and a work copy at `work/Clause-Driven-LLM`, both inside `studies/clause_lm/` and both ignored by git. The work copy differs from upstream in an added data module and in a change to the training script. Both differences are published: the module as `studies/clause_lm/src/clause_driven_llm/cdllm_data__init__.py`, and the change as the patches `train_controller.state1.patch` and `train_controller.patch` in the same folder. The [README of the study](../studies/clause_lm/README.md) explains how they apply, and its [results page](../studies/clause_lm/docs/results.md) says which run records hold their hashes.
