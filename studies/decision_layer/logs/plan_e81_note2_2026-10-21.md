## Why (05:58 UTC)

- **The edge pick:** on MultiWOZ dev both LR baselines picked C 0.001, the smallest value of their grid (0.001 to 100):
  - C4 bits: 0.3586 (results/explore/dryrun/dry_e77mwoz_lr_mem_c4);
  - refined bits: 0.3643 (results/explore/dryrun/dry_e82mwoz_lr_mem_a3B).
- **What it could mean:** LR may be under-tuned there. That would flatter the TM in every TM - LR line on MultiWOZ and
  in B2's bar.
- **Timing:** this was known before any e81 number. At this note there are 0 e81 rows and 0 e81 dry runs.

## What

- **The runs:** LR on the same view-B bits, MultiWOZ dev, one C per job (6 jobs in logs/jobs_e81x_lr_lowC.txt), for
  the refined (a3B) and the C4 bit sets.
  - C 1e-3 reruns the old edge value. It should reproduce the old row exactly; if it does not, that is reported.
  - Then C 3e-4 and C 1e-4.
- **The code path:** the old rows' own, abcd_confirm.py --dry-run. Dev stands in for test, and no test split is read.
- **The pick:** the best of the three, with ties going to the larger C.
  - If the best is C 1e-4, it is reported "again at the grid's edge", and the grid is not extended further.
- **The report** is `scripts/e81x_report.py`, read only. It is printed beside B2, never in its place, and B2 stays as
  frozen (against 0.3643). There is no rule. It prints:
  - for each C, LR's dev accuracy;
  - the refined TM at e81's pick, the same value e81_pick.py's B2 line uses, minus the best LR and minus the old LR;
  - for C4, the TM at T = clauses (16k, mean of seeds 1-2) minus the best LR.
- **A side reading:** it also tests the label-set diagnostic's reading, that more regularisation helps on these bits
  (project notes, not published).
- **When:** after the e81 driver's "e81 GPU stages done", alone on the GPU, through
  `scripts/seq_queue.sh logs/jobs_e81x_lr_lowC.txt logs/e81x_queue.log`. That is about 15 GPU-minutes: 6 jobs at 2.3 to
  2.5 min each, as e77a's and e82's LR jobs took.
  - It is not run on the CPU, because abcd_confirm.py fits LR on the GPU (dl.linear.fit_logreg, device cuda).
