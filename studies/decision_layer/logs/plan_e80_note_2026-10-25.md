## Exclusivity and the order

- **The shared GPU lock allows overlap.** gpu_run.sh's "shared" mode is "training and correctness runs, may overlap"
  (../tm_language_model/scripts/gpu_run.sh line 4), and seq_queue.sh uses it (its line 24). Between jobs, seq_queue.sh
  can wait 50 s at a time on its CPU gate with the GPU empty.
- **So exclusivity comes from the start order.** Each chain stage is started only when no other GPU chain or queue is
  running or waiting. The order is: e87 a0, then bdry, then b; then the e80 dry run, then e80; nothing
  else on the GPU in between. The slot is booked in the project's GPU queue.
- **In addition, the chains exclude each other.** The e80 stages refuse while an e87 GPU stage holds its lock
  (logs/e87n_a0.lock, e87n_bdry.lock, e87n_b.lock), and e87's GPU stages refuse while an e80 stage holds its lock.
- **A manual condition, already met:** start only after logs/e86_star_end.log exists. e86's STAR chain wrote it at
  2026-10-25T12:50:52Z (its file time).
