### The budget knob: scripts/e87b_run.py

- **What it does.** It patches dl.tm.CoTM in its own process and then runs the job's script, as scripts/knob_run.py
  does. tm.py, tm_chunkbudget.py, knob_run.py and every run script stay byte for byte.
  - It sets neg_sampling (hardest or random) before the original __init__, so the row's cfg records it.
  - It refuses a machine without an exact budget, or with a negated cap.
  - It calls dl.tm_chunkbudget.enable on each machine.
  - It counts the chunked budget updates: one per training step.
- **Selection.** In the chunked update it rebinds tm_chunkbudget's select_k to select_k_skip0. That function gives
  dl.tm.select_k's result for every row, but does not sort the rows whose allowance is 0, since they keep nothing.
  - The random keys are drawn as before, so training is the same bit for bit.
  - The test shows this on 790 calls with ties and on two whole trainings, compared array by array. In those
    trainings 2,914 of 3,330 over-budget rows had an allowance of 0 (a small synthetic task, not the agent's data).
  - The dry run repeats one tiny job with --plain-select (dl.tm.select_k unchanged) and compares the two models on
    the GPU.
  - With the trim start every clause starts at the budget, so most sorts should be skipped.
- **The run record** (results/explore/e87/b_runs/<tag>_seed<k>.json) holds the knobs, CHUNK_ELEMS, each machine's
  sizes and count of chunked updates, the argv, the model file and its SHA-256, and the start and end times.
  - It is written only after the script ends without an error.
  - An existing record or model file is refused before the script starts. So a second try of a job (scripts/seq_queue.sh
    retries a failed job once) cannot overwrite the first try's files.
- --chunk-elems sets dl.tm.CHUNK_ELEMS for the dry run's tiny jobs only.
- Test: tests/test_e87b_run.py PASSED (logs/test_e87b_run.out). It covers:
  - tm.py's own chunked update refuses the exact budget;
  - a small machine forced into 9 chunks keeps every clause at 3 literals or fewer after every step, runs the chunked
    budget update at every step, and learns a small task;
  - select_k_skip0 against dl.tm.select_k, and the two trainings compared bit for bit;
  - the refusals, and end to end with a made-up target script.

### The pruned scoring and the check: scripts/e87b_check.py

- **Modes:**
  - `--dry`: after the dry run; no rule, writes nothing;
  - `--bar-only`: after the nine jobs; the bar; writes results/explore/e87/partb_bar.json. This is the mode of this pass;
  - no option: after Part A as well; the bar and the kill rule; writes results/explore/e87/partb.json. Not run in this
    pass; kept unchanged for a later one.
  - CPU only. It refuses without this note's freeze record, or when this note's text does not hash to it. It
    refuses to overwrite its output.
- **Two passes.** Every check of every job of all three datasets runs first, and so do the checks of Part A's files
  and the recomputed accuracies. No number is printed except in a refusal message. Then come the scores, the rules and
  the report.
- **Checks on every job:**
  - exactly one row per tag and seed, written after this note's freeze;
  - the row's dataset, encoder, parts, lex_k, init, cfg and table are the cell's;
  - its train and dev bits equal A0's, and A0's equal the registered C4 arm's (seed1.json) and A0's own arrays;
  - A0's L2 LR dev accuracy equals its LR dev row's;
  - the run record: the negative rule, select skip0, CHUNK_ELEMS, one chunked machine with the exact budget, one
    chunked budget update per training step (epochs x ceil(train rows / 128)), a start after the freeze, and the
    model file's SHA-256 now;
  - the model's cfg, names and buttons equal the row's and A0's;
  - its dev accuracy, recomputed on A0's dev bits with e87_readability.tm_part, equals the row's acc exactly.
- **The pruned scoring (the plan's registered reading):** every clause with more than 3 literals gets weight 0. The
  machine is then scored on dev with e87_readability.tm_part: the decision, the receipts, the coverage and S1's point.
  - For the statistics a pruned clause is also emptied, so it neither fires nor counts in clause precision. The
    decisions and receipts are the same either way.
  - A warning is printed for any clause over 3 literals.
  - e87_readability.py is imported, not changed.
- **Reported with no rule:**
  - the unpruned scores, the coverage curve, the clause statistics, and the literal-count distribution (0, 1, 2, 3,
    over 3, longest);
  - any job the queue started twice ("start (try 2)" in logs/e87b_queue.log);
  - B's STAR seed 1 against the dry run's full-size STAR job, at their first evaluation (see the job lines).
- **The bar (the plan's):** on at least 2 of 3 seeds, the pruned dev accuracy is at least A0's L2 LR dev accuracy

## Exclusivity and the order

- **The shared GPU lock allows overlap.** gpu_run.sh's "shared" mode is "training and correctness runs, may overlap"
  (../tm_language_model/scripts/gpu_run.sh lines 4-5), and between jobs seq_queue.sh can wait 50 s at a time on its CPU
  gate with the GPU empty. The 3-empty-GPU rule holds only at a stage's start.
- **So exclusivity comes from the start order.** Each chain stage is started only when no other GPU chain or queue is
  running or waiting. The order is: e87 a0, then bdry, then b; then the e80 dry run, then e80; nothing
  else on the GPU in between. The slot is booked in the project's GPU queue.
- **In addition, the chains exclude each other.** An e87 GPU stage (a0, bdry, b) refuses while an e80 stage holds its
  lock (logs/e80n_dry.lock, logs/e80n_run.lock), and the e80 stages refuse while an e87 GPU stage holds its lock.
- **seq_queue.sh's per-job CPU gate fails open:** if cpu_load.py prints nothing, its awk compares an empty value and
  passes. The chain's own gates fail closed. seq_queue.sh stays as pinned.
- **Starting a0 after logs/e86_star_end.log exists is a manual step, already met:** e86's STAR chain wrote that file
  at 2026-10-25T12:50:52Z (its file time).

## The chain and its stages

e87_chain.sh (project notes, not published) runs one stage per start.
- **Each stage:**
  - holds a lock (logs/e87n_<stage>.lock), so a second chain of the same stage cannot start while one runs;
  - refuses without this note's freeze record (the SHA-256 of this text must equal the record's);
  - refuses unless the files it runs equal this note's pins: every repository row of the hash table below (sha256sum
    of the path in the first column, a trailing parenthesis removed), the chain itself against its own row, and the
    stage's job file present in the table;
  - refuses when a file on e87's path (src/dl/, scripts/e87*, abcd_explore, table_run, seq_queue, cpu_load,
    diff_frozen) changed since this note's freeze record (scripts/diff_frozen.py);
  - refuses a second start: its end log or an output exists. A stage that ended before writing any output may start
    again, keeping its old end line: refused, a handoff or wait timeout, a gate timeout, or killed while waiting.
- **It writes** "e87n <stage> end: <branch> <UTC> exit <code>" to logs/e87n_<stage>_end.log. The old
  logs/e87_a0_end.log and logs/e87_a_end.log stay as they are.
- **Any end stops the stage's running commands**, which run in their own process groups (setsid). On TERM, HUP or INT
  the end line says "killed by signal <name>".
- **Before each GPU stage it waits for 3 empty-GPU checks in a row.** The GPU and CPU checks fail closed: an
  nvidia-smi or cpu_load.py error counts as busy.
- **The CPU gate** (at most 4.5 cores over 10 s) comes before every CPU command, the dry check and the bar check
  included.

The stages run in this pass, in this order:
1. **a0** (GPU): A0 for abcd, star and multiwoz. It stops at the first failure.
2. **bdry** (GPU): waits for a0's done line; the dry run; the CPU gate; `e87b_check.py --dry > logs/e87b_dry_check.out`,
   which must end "all dry checks passed". Read its projection line before step 3.
3. **b** (GPU): needs bdry done and the dry check's pass line. The nine jobs; the CPU gate;
   `e87b_check.py --bar-only > logs/e87b_bar.out`.

Not started in this pass (kept for a later one): **a** (CPU, Part A; with A_PARALLEL=1 it waits for b's done line,
