# e71 v2: dated note (2026-10-19): a crash on the first off-window state, the fix, and one corrected count

## 1. What happened

- **The crash:** the run (tag e71v2, TM seed 1, started 03:31 UTC) exited with code 1 at 07:31:54 UTC.
  `scripts/verify_enum.py` raised KeyError 'ja' in `search` / `insertions` (line 213), on state 2485.
- **Where it stood:** 126 of the 200 sampled states were done (355 rows), every one of them in-window. State 2485 is
  the 127th state in the sorted sample and the first whose latest customer utterance u is outside the last 3 turns.
- **The cause:** `TextModel.split` sets "ja" (the word after u in the last 3 turns) only for in-window states, and
  `insertions` read `s["ja"]` eagerly, as an argument to `word_cols`. `word_cols` itself returns no columns for an
  off-window state, so the value is never used there.
  - Every other use of "ja", "jb", "before", "after", "recent_fixed", "fixed_uni" and "fixed_bi" (verify_enum.py and
    verify_local.py) sits inside an in-window branch.
- **Why no pre-check caught it:** pre2 (30 random dev states) calls `search` and passed, so its states were all
  in-window. `pre` does not call `insertions`.

## 2. The fix (two lines; verify_enum.py 94e9b1e223a37ed0 to 99ba658230306a88)

```
213: word_cols(last, s["ja"])  ->  word_cols(last, s.get("ja"))
222: word_cols(w1, s["ja"])    ->  word_cols(w1, s.get("ja"))
```

- **Done states are unaffected:** where the key exists, `s.get("ja")` is `s["ja"]`, so the 126 states already done
  would give the same rows. No state is rerun: the run skips every (tag, seed, state, group) already in the results
  file.
- **Off-window states now run** with only the customer field (xcust) changing, as the plan says.

  against cpu_tm_fast's;

  random first words.

The run resumes only if every count is exact.
