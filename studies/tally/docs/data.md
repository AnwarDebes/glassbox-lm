# Data of the tally study

No dataset, derived data file or model file of the study is distributed. The code reads data from three places: the data folders of the tm_language_model study, one run folder of the hierarchical_tm study, and the folder `data/` of this study, which the repository ignores. For each dataset this page says what it is, which line of work uses it, where the code expects it, which source and version a file on disk records, which SHA-256 a record holds, and what is known about its licence.

Paths are relative to the study folder. "Not recorded" means that no file of the repository and no run record gives the value. A licence is named only where a file on disk states one; otherwise the entry reads "licence to be confirmed". The run folders are not distributed, so the hashes that only they hold are printed here. Whether a rebuild from a clone gives the recorded hashes has not been tested.

## Penn Treebank and its splits

The text is the word-level Penn Treebank of the Mikolov preprocessing, one sentence per line, with the token `<unk>`. `src/tally/ptb.py` appends `<eos>` to every sentence and builds the vocabulary as the sorted set of the words of the standard training file, so the word ids do not depend on the split; the vocabulary has 10,000 entries, `<unk>` and `<eos>` included (`metrics.json` of `20261015T072513Z_a1_baseline_check`, key `V`).

The splits are those of `src/tally/ptb.py`. The standard training file is cut into blocks of 100 sentences, and a permutation with seed 20261015 assigns 5% of the blocks to the calibration split, 5% to the dev-test split and the rest to the training split. The standard validation file is the tuning split. The standard test file is not opened: the module has no function that reads it. `registrations/T0.md` gives the sizes: 379 blocks with 836,253 tokens for training, 21 blocks with 46,925 tokens for calibration, 21 blocks with 46,411 tokens for dev-test, and 73,760 tokens for validation. The run `20261015T072513Z_a1_baseline_check` records the same token counts for the training, calibration and validation splits (`metrics.json`, key `splits`); no run file that this page cites holds the size of the dev-test split.

T0 builds its inputs and labels from these splits (`src/tally/t0/data.py`): the 1,000 most frequent words of the training split and one class "other" as the 1,001 classes, an add-one unigram distribution over the other 9,000 words, and the previous 3 words as 3,003 input bits, all counted on the training split. A1 writes the splits for KenLM as text files, one sentence per line, with `<eos>` dropped and the word `<unk>` renamed `UNKPTB` (`src/tally/floor/kenlm.py`). A2 builds its category codes from the training split only (`src/tally/floor/codes.py`).

## Data of B6

`src/tally/b6/prepare.py` cuts the calibration and the validation split from the official training file of each dataset, stratified by class with seed 20261015, and uses the official test file as the dev-test split. It writes the splits and the views to `data/b6/<dataset>/`, together with `manifest.json`, which holds the SHA-256 of the sources and of every output file, the split sizes, the package versions and a count of duplicates. The two manifests were written on 2026-10-15 at 07:07:16 UTC (Fashion-MNIST) and 07:07:56 UTC (AG News) (key `utc`).

| Dataset | Train | Calibration | Validation | Dev-test | Held out per class for calibration and for validation | Exact duplicates of held-out items in the training split |
|---|---|---|---|---|---|---|
| Fashion-MNIST | 50,000 | 5,000 | 5,000 | 10,000 | 500 | none in dev-test |
| AG News | 108,000 | 6,000 | 6,000 | 7,600 | 1,500 | 8 in dev-test, 14 in validation |

All values are read from the manifests (keys `sizes`, `held_out_per_class` and `duplicates`); the duplicates are counted and not removed. The views of Fashion-MNIST are adaptive Gaussian thresholding, an 8-level thermometer code, HOG features and the raw pixels; those of AG News are binary word unigrams, word bigrams and character 4-grams, each reduced by a chi-squared selection fitted on the training split only (`src/tally/b6/prepare.py`). Fashion-MNIST has 25 output files and AG News 22 (key `outputs`).

The dev-test views exist, and no run of the study has scored them: the only B6 runs are timing runs, which read the training split. `src/tally/b6/prepare.py` reads the AG News test file directly from the cache of tm_language_model, and not through the loaders of that study, which count every read of a test split.

## Data of A2

The four files in `data/a2_external/` serve the reports on the category codes and the predefined code: SimLex-999 and WordSim-353 for the correlation with human similarity ratings, the Brown corpus and the universal tagset mapping for the part-of-speech tagger. This study records no download address for them. SimLex-999 and WordSim-353 have the SHA-256 values of the corresponding records of tm_language_model, which name their addresses; the Brown corpus and the tagset mapping match no record of the repository.

The code `orgroups` reads the word groups of one hierarchical_tm run from a file in a run folder of that study (the rows whose role is `model` and whose run is `20261002T050235Z_e4_head_sa_s1_scoreP100`). The file is not distributed, so this code cannot be rebuilt from a clone.

The folder `data/a2_codes/` holds the codes of the A2 smoke run only: 30 files whose names begin with `smoke_`, each code an array with a JSON file that records the SHA-256 of its sources and of the array itself (`src/tally/floor/codes.py`). These JSON files hold the SHA-256 of the Penn Treebank training and validation files as well.

## Derived files and model files

`data/a1_kenlm/` holds the text files that A1 writes for KenLM (`train.sent.txt`, `calib.sent.txt` and `valid.sent.txt`) and the KenLM models of order 3 and 5 as ARPA and binary files, with the logs of `lmplz`. No record holds their SHA-256, and the KenLM version is not recorded.

Trained models are run outputs. The tuning and final runs of T0 hold the trained machine (`model_last.pkl`) and the final runs the bits per position (`bits.npz`) and, for the coalesced machine, the clause outputs (`fired_<split>.npz`). None of them is distributed.

## Known problems of the data

- The Penn Treebank text is pinned to a ref name and not to a commit (see the data page of the repository). The run records of this study hold the SHA-256 of the validation file only, because the run logger keys `data_hashes.json` by file name and both files are named `text.utf8`; the SHA-256 of the training file is recorded in the A2 smoke run and in the code files of `data/a2_codes/`.
- The four files in `data/a2_external/` have no recorded download address in this study. Two of them match records of tm_language_model; the Brown corpus and the tagset mapping match none.
- The Fashion-MNIST test file has a recorded repository and revision, but no recorded address or time of download.
- In AG News, 8 dev-test texts and 14 validation texts have an exact duplicate in the training split.
- The records of tm_language_model disagree on the licence of AG News.
- The KenLM files of A1 have no recorded hash, and the KenLM version is not recorded.
- The OR-group file of A2 is in a run folder of hierarchical_tm, which is not distributed.
